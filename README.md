# Group Buying — колективні закупівлі, Варіант 16

**Group Buying** допомагає мешканцям будинку або району об’єднати замовлення в одного постачальника, досягти мінімального гуртового порогу та отримати спільну доставку до точки видачі.

## Ролі та сценарії

| Роль | Основні можливості |
| --- | --- |
| **Учасник** | Перегляд каталогу, приєднання до збору, зміна кількості або вихід до фіксації гуртової ціни, оплата частки, відстеження замовлення та підтвердження отримання. |
| **Організатор** | Створення і скасування власних закупівель, перегляд учасників та часток доставки, фіксація гуртової ціни після досягнення порогу, оформлення повністю оплачених партій. |
| **Кур’єр** | Прийняття готової партії, оновлення статусу доставки до точки видачі, перегляд отримувачів і винагороди, облік виплат на картку або IBAN. |

Життєвий цикл: **Збір учасників → Оплата → Оформлення → Доставка → Точка видачі → Отримано**. Учасник підтверджує отримання окремо; після отримання всіма учасниками закупівля закривається. Збір, що не досяг порогу до завершення таймера, скасовується.

## Розрахунок ціни й доставки

До досягнення порогу збір оцінюється за роздрібною ціною. Коли `collected >= threshold`, інтерфейс переходить на гуртову ціну. Економія учасника:

```text
(retailPrice − wholesalePrice) × quantity
```

Частка доставки розподіляється за вартістю кошика за актуальною ціною:

```text
round(deliveryTotal × (userSubtotal / max(totalCollected, thresholdAtCurrentPrice)))
```

Коли поріг покритий, розрахунок використовує гуртову ціну для всіх учасників. Залишок від округлення коригується на найбільше замовлення, щоб сума часток дорівнювала доставці партії.

## Технології

- React 19, Vite 8 та Tailwind CSS 4
- Supabase Auth, PostgreSQL, RPC і Realtime для багатокористувацького режиму
- LocalStorage як автономний режим для навчальної демонстрації
- Lucide React, Oxlint і Node.js `node:test`

## Швидкий старт

Потрібен Node.js і npm.

```bash
npm install
npm run dev
```

Команди якості й production-перегляду:

```bash
npm test
npm run lint
npm run build
npm run preview
```

Для автономного режиму залиште `.env` відсутнім. Для Supabase скопіюйте `.env.example` у `.env` та вкажіть `VITE_SUPABASE_URL` і публічний `VITE_SUPABASE_ANON_KEY` / publishable key. **Ніколи не додавайте `.env` або `service_role` key у GitHub чи до клієнтської збірки.** Після редагування `.env` перезапустіть Vite.

## Supabase

1. Створіть окремий Supabase-проєкт для застосунку.
2. Запустіть [supabase/schema.sql](supabase/schema.sql) у SQL Editor. Скрипт створює таблиці `gb_users`, `gb_purchases`, `gb_orders` і `gb_courier_payouts`, політики доступу, обмеження, RPC для бізнес-операцій та публікацію Realtime.
3. У Supabase Auth вимкніть підтвердження email, якщо для навчальної демонстрації потрібна миттєва реєстрація. Додайте домен розгорнутого сайту до дозволених адрес Auth.
4. Налаштуйте змінні середовища у локальному середовищі та на обраному хостингу.

## Архітектура безпеки та межі MVP

- Рольові зміни виконуються через серверну `SECURITY DEFINER` RPC із перевіркою `auth.uid()` і ролі; у таблицях ввімкнено RLS.
- Пароль у Supabase обробляє Supabase Auth. У LocalStorage пароль зберігається як PBKDF2-хеш із випадковою сіллю.
- Сесія Supabase має окремий storage key для кожної вкладки. Realtime оновлює дані закупівель і замовлень, не перемикаючи активного користувача вкладки.
- URL зображень приймаються лише за HTTP(S); React рендерить текст як текст, без `innerHTML`.
- Виплати зберігають тільки масковані реквізити: тип, бренд, власника, останні чотири цифри та метадані транзакції. Повний PAN/IBAN не записується у сховище.
- CSP і захисні HTTP-заголовки налаштовані для Vercel та Netlify.
- Екран карткової оплати і виплати в цьому навчальному MVP **не виконує реального руху коштів**. Для реальних платежів потрібні платіжний провайдер, серверна інтеграція, належні правові процеси та перевірка PCI DSS; не вводьте реальні карткові дані в навчальну демоверсію.

Список джерел: `src/components/`, бізнес-логіка в `src/utils/` та `src/lib/`, сховище й Supabase інтеграція — `src/services/dataService.js`, SQL схема — `supabase/schema.sql`.

## Деплой

### Vercel

1. Імпортуйте GitHub-репозиторій у Vercel.
2. Додайте `VITE_SUPABASE_URL` та `VITE_SUPABASE_ANON_KEY` у Environment Variables для потрібних середовищ.
3. Команда збірки — `npm run build`, директорія результату — `dist`.
4. `vercel.json` налаштовує SPA fallback і security headers.

### Netlify

1. Під’єднайте GitHub-репозиторій у Netlify.
2. Build command — `npm run build`, publish directory — `dist`.
3. Додайте ті самі публічні змінні середовища для збірки.
4. Файли `public/_redirects` і `public/_headers` налаштовують SPA fallback і security headers.

```text
  lib/            Авторизація, гроші, замовлення й сховище

tests/
  app.test.mjs    Автоматичні unit та логічні тести
```
